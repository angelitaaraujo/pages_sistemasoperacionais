🎓 O Problema do Buffer Limitado (Produtores e Consumidores)

Este é um dos problemas mais célebres de concorrência na Ciência da Computação, formulado originalmente por Edsger Dijkstra em 1965. Ele modela a cooperação entre processos concorrentes que se comunicam através de uma região de memória compartilhada de tamanho fixo (buffer).

1. As Duas Condições de Bloqueio

  • Buffer Cheio: Se todos os espaços estiverem ocupados, os produtores não podem depositar mais itens. Devem ser bloqueados para não sobrescrever dados.
  • Buffer Vazio: Se o buffer estiver vazio, os consumidores não têm o que retirar. Devem ser bloqueados até que um produtor insira algo.

2. A Solução com Semáforos

  • sem_t mutex = 1: Garante que apenas 1 processo (produtor ou consumidor) modifique os ponteiros do buffer por vez.
  • sem_t empty = N: Conta quantas posições livres restam no buffer.
  • sem_t full = 0: Conta quantos itens estão prontos para consumo.

3. Por que Ocorre Race Condition?

Sem semáforos, duas threads podem ler a mesma posição in ao mesmo tempo, gerando perda silenciosa de dados. Além disso, operações como count++ e count-- no nível assembly realizam 3 instruções (carregar, somar, salvar). Interrupções no meio do ciclo corrompem a integridade dos dados!

Pseudocódigo Clássico com Semáforos (Padrão POSIX Threads)
Thread Produtor()
while (true) {
  item = produzir_item();
  sem_wait(&empty);  // decrementa 'empty', dorme se 0
  pthread_mutex_lock(&mutex); // entra na reg. crítica

  buffer[in] = item;
  in = (in + 1) % BUFFER_SIZE;

  pthread_mutex_unlock(&mutex); // sai da reg. crítica
  sem_post(&full);   // avisa consumidor acordando-o
}
Thread Consumidor()
while (true) {
  sem_wait(&full);   // dorme se não houver itens
  pthread_mutex_lock(&mutex); // entra na reg. crítica

  item = buffer[out];
  out = (out + 1) % BUFFER_SIZE;

  pthread_mutex_unlock(&mutex); // libera o buffer
  sem_post(&empty);  // avisa produtor: há vaga livre
  consumir_item(item);
}
